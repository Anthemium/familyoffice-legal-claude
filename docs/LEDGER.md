# Реестр действий (ledger)

Неизменяемый журнал всех действий в кабинете семьи и в Студиоло. Каждый шаг получает собственный ID,
время, устройство и подпись и встраивается в хэш-цепочку. Принцип тот же, что у блокчейна
(каждая запись содержит хэш предыдущей), но без публичной сети и майнинга: журнал ведёт коллегия,
а его неизменность подтверждают внешние метки времени.

Демо: `/{ru,en,hu}/ledger/`, раздел «Реестр» в Студиоло, карточка «Реестр действий» в кабинете семьи.
Код: `src/lib/ledger/core.ts` (алгоритмы), `src/lib/ledger/client.ts` (демо-хранилище в браузере),
`prisma/migrations/ledger.sql` (рабочая база).

## Что записывается

| Событие | Когда | Причина (parents) |
|---|---|---|
| `session.start` | вход в кабинет | — (содержит устройство и открытый ключ сессии) |
| `session.end` | выход / таймаут | вход |
| `document.upload` | загрузка файла | вход |
| `document.open` | просмотр / скачивание | вход + загрузка этого документа |
| `message.send` | отправка сообщения | вход |
| `message.open` | открытие сообщения получателем | вход + отправка этого сообщения |
| `template.download` | выдача шаблона из библиотеки | вход |
| `shield.call` | вызов «Щита 24/7» | вход |

Поля события: `id` (UUIDv7), `seq`, `ts`, `type`, `actor` (кто и в какой роли), `session`,
`device` (ID устройства, браузер и ОС, экран, язык, часовой пояс, отпечаток, IP — на сервере),
`subject` (документ или сообщение: ID, название, **SHA-256 содержимого**), `perimeter` (A/B),
`parents`, `prevHash`, `hash`, `sig`.

Содержимое документов и сообщений в журнал не попадает — только хэши. Поэтому журнал можно показать
суду или аудитору, не раскрывая адвокатскую тайну, а подлинность любого файла проверяется
пересчётом его SHA-256.

## Как обеспечивается неизменность

1. **Хэш-цепочка.** `hash = SHA-256(канонический JSON события без hash и sig)`, и в событие входит
   `prevHash` предыдущего. Изменённая запись перестаёт совпадать со своим хэшем; если злоумышленник
   пересчитает хэш, разорвётся связь со следующей записью.
2. **Подписи.** В демо — ключ сессии ECDSA P-256 (открытый ключ записан в `session.start`).
   В рабочей версии — две подписи: пользователя (WebAuthn, аппаратный ключ) на критичных действиях
   и сервера коллегии (ключ в KMS) на каждом событии.
3. **База.** Таблица только на добавление: триггеры запрещают UPDATE/DELETE/TRUNCATE, проверяют `seq`,
   `prev_hash` и наличие причин; запись идёт под advisory lock — один писатель за раз.
   Время ставит сервер (`clock_timestamp()`), а не браузер.
4. **Якорение.** Раз в час (и по запросу) сервер считает корень Меркла новых событий, подписывает его,
   получает **квалифицированную метку времени** по RFC 3161 и кладёт копию в S3-бакет
   с Object Lock (WORM). После этого даже администратор базы не может незаметно переписать историю:
   корень разойдётся с заверенным.

## Юридическое использование

- **Выписка** — JSON со всеми событиями периода, корнем Меркла, результатом проверки и алгоритмами.
  Для одного события — доказательство включения (путь до заверенного корня): суд видит событие
  и его место в журнале, остальной журнал не раскрывается.
- **Метка времени:** для Венгрии и ЕС — квалифицированный поставщик по eIDAS (ст. 41–42: презумпция
  точности времени и целостности данных); для России — аккредитованный удостоверяющий центр
  со службой штампов времени по 63-ФЗ «Об электронной подписи».
- В российском процессе выписку дополнительно можно закрепить нотариальным обеспечением доказательств.
- Независимая проверка: `verifyLedger()` из `core.ts` работает без сервера коллегии — достаточно выписки.

## Персональные данные

IP-адрес, устройство и отпечаток — персональные данные (152-ФЗ, GDPR). Чтобы право на удаление
не ломало цепочку, в рабочей версии они хранятся отдельно в зашифрованном виде (ключ на пользователя),
а в хэшируемое тело события попадает только их хэш-обязательство. Удаление данных — уничтожение ключа
(crypto-shredding): запись остаётся проверяемой, данные — нечитаемыми. Срок хранения задаётся политикой
коллегии.

## Ограничения демо

- Журнал хранится в `localStorage` браузера, поэтому он свой у каждого устройства. Подписи делаются ключом
  сессии, IP не фиксируется, якорения нет.
- `session.end` пишется при выходе из Студиоло; при закрытии вкладки в рабочей версии его ставит сервер
  по таймауту.
- Кнопка «Симулировать подмену» меняет запись в обход системы — так видно, что проверка её ловит.
